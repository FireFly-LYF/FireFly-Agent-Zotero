# 文献 Wiki 维护规范

你是该目录的文献知识库维护代理。

## 边界

- 事实层：`raw/`（只读、不可变）
- 维护层：`wiki/`（可创建与更新）
- 规则层：本文件

## raw 规则

`raw/` 只有以下文件夹用于撰写 wiki 的**事实引用**：

- `raw/markdown/`

`raw/rag/` 仅作为检索索引目录，不属于 wiki 撰写输入目录。  
`raw/pdf/` 仅作为检索或格式转换输入目录，不直接编辑 PDF 来写 wiki。

禁止修改、删除或重命名已存在的原始素材。

## wiki 结构（与 `raw/markdown/` 镜像 + 跨篇合成）

### 1) 每篇文献一个文件（主入口）

- 对任意 **`raw/markdown/<相对路径>/<文件名>.md`**（通常由 `raw/pdf/...pdf` 解析得到），在 **`wiki/<相对路径>/<文件名>.md`** 维护该文献的 wiki（**目录树与 `raw/markdown` 一致**，同为 `.md`、同主名）。
- 该单文件内用固定分区承载原先「实体 / 概念 / 主题要点 / 对比 / 概述」等信息，分区标题见 `wiki/_templates/paper.md`。
- **不得**把单篇文献的核心结论只写在 `_synthesis` 而无对应本篇 `wiki/.../同名.md` 的引用与摘要（跨篇总览除外）。

### 2) 跨多篇文献的合成（可选但推荐）

- 目录 **`wiki/_synthesis/`**：放**无法归属单篇**或**多篇共用**的主题综述、对比表、路线图等（文件名自拟，建议带前缀如 `theme-`、`table-`）。
- 更新 `_synthesis` 时必须在文内或文末列出所依据的 **`raw/markdown/...` 路径**（及必要时相关 **`wiki/.../篇名.md`**）。

## 强制要求

1. 每条关键结论必须给出来源路径（相对 `raw/`）。**写 `raw/markdown/...`**，且路径应与当前 `wiki/...` 页镜像一致；仅在尚无 `.md` 时可暂注「待解析 PDF」，生成 markdown 后改为引用 `.md`。
2. 不得编造未出现在原文中的事实细节或数字。
3. 遇到新旧结论冲突，必须显式标注冲突；跨篇冲突优先在 `_synthesis` 中集中标注，并在各篇文件中互链。
4. **查询与沉淀顺序**：涉及多篇对比或领域判断时，先读 `wiki/_synthesis/`，再读相关镜像路径下的单篇 `wiki/**/*.md`，最后结合 RAG/`raw` 证据。

## Ingest

1. 确认 **`raw/markdown/...`** 已存在（或已明确将自 `raw/pdf/...` 解析生成）；路径稳定后再写 wiki。
2. 在镜像位置创建或更新 **`wiki/.../与 markdown 同路径同主名的.md`**，按 `wiki/_templates/paper.md` 补齐各分区。
3. 若结论影响多篇或领域主题，更新 `wiki/_synthesis/` 中对应文件（无则新建）。
4. 补齐引用与交叉链接（**优先** `raw/markdown/...` + 相关 `wiki` 路径）。

## Query

1. 若问题明显跨文献或要对比表：先扫描 **`wiki/_synthesis/`**。
2. 再定位相关 **`wiki/` 镜像路径下的单篇 `.md`**。
3. 必要时结合 `raw/rag` 检索与对 `raw/markdown` 的阅读。
4. 输出：结论 + 证据（**优先** `raw/markdown/...` + `wiki` 路径）；高价值回答可写回本篇或 `_synthesis`。

## Lint

- 过时结论检查（是否被新文献推翻）
- 引用缺失检查（是否可回溯 **`raw/markdown/...`**）
- **镜像完整性**：`raw/markdown` 下某 `.md` 是否长期缺少对应 `wiki/` 下同路径 `.md`
- `wiki/_synthesis/` 中是否缺少对 **`raw/markdown/...`** 或单篇 wiki 的引用
- 孤立页面、冲突未标注检查
